01 / UPGRADED ARCHITECTURE

Unified Orchestration & Execution Context

High-Level Component Diagram (v1.1)

Key Upgrade: Unified Orchestration CRITICAL

  • ✓ Workflow Engine as Source of Truth: Replaced raw BullMQ with Temporal/Inngest/Trigger.dev for native human-in-the-loop support, durable execution, and automatic retries.
  • ✓ Explicit Run ID (GenerationSession): Every idea → publish attempt is tied to a single run_id. Enables full traceability of AI costs, judge scores, and platform responses.
  • ✓ Strict Adapter Interface: Platform adapters are now pure I/O behind a common contract. The orchestrator doesn't know about Instagram's API quirks; it just calls adapter.publish().

Key Upgrade: Data Model Additions NEW

  • ✓ GenerationSession: Ties together the original 4-line idea, master content, 8 adaptations, judge scores, and final publish status.
  • ✓ StatusTransitionLog: Immutable audit trail of every state change (who/what triggered it, timestamp, reason).
  • ✓ Platform-Specific Sub-states: PlatformPost now tracks its own state (e.g., PUBLISHING_IG, FAILED_IG), allowing one platform to fail without rolling back the entire batch.

New Transition Rules
  • → DRAFT → GENERATING: User submits idea. UI shows streaming/processing state. Allows cancellation.
  • → READY → APPROVED → READY: First-class transition. If a user edits an approved post, it reverts to READY for re-evaluation.
  • → SCHEDULED → PUBLISHING: Prevents double-publishing race conditions. Locks the row during the API call.
  • → ANY → CANCELLED: Soft delete for abandoned posts. Preserves analytics linkage without cluttering active queues.
Platform Sub-States

Because one idea spawns 8 platform posts, the parent Post can be SCHEDULED while individual PlatformPost entries have their own states:

PUBLISHING_IG PUBLISHED_LI FAILED_TT READY_X 6

This ensures a TikTok API failure doesn't block or rollback a successful LinkedIn publish.

03 / AI ORCHESTRATION UPGRADES

From Concept to Closed-Loop System

1. Prompt Registry (Versioned) UPGRADED

  • → Versioning: prompt_id + version (e.g., master_content.v7).
  • → Schema Binding: Every prompt is strictly bound to an input/output Zod schema.
  • → Canary Rollouts: Route 10% of traffic to v8 to A/B test prompt efficacy before full deployment.

2. Model Router (Intelligent) UPGRADED

  • → Primary + Fallback: Auto-failover to secondary provider if primary is rate-limited or down.
  • → Cost vs. Quality Routing: Route high-stakes (LinkedIn long-form) to Tier 1 (Opus), and mechanical tasks (hashtag generation) to Tier 3 (Haiku).
  • → Per-Platform Preferences: Configurable model mapping per platform type.

3. Judge Model (Elevated) CRITICAL

  • → Separate & Cheaper: Runs as a fast, post-generation step using a cheaper model (e.g., Sonnet or Haiku).
  • → Scoring Criteria: Uniqueness across platforms, brand voice match, hook strength, CTA clarity, policy risk.
  • → Hard Gate: Only promotes status to READY if Judge score ≥ threshold. Otherwise, auto-retries with adjusted context or flags for human review.

4. Context Assembler (The Moat) NEW

  • → Dynamic Context Injection: Before any generation, this service pulls:
  • • Workspace brand voice & forbidden phrases.
  • • Top 3 performing past posts (via vector store similarity).
  • • Recent failures/learnings (e.g., "Last TikTok hook was too salesy").
  • • Real-time platform-specific constraints.
